# Роадмап трансформации IT-ландшафта «Будущее 2.0»

## Общая хронология

Файл: [roadmap.drawio](roadmap.drawio)

Диаграмма Ганта охватывает 12 месяцев (Май 2026 — Апрель 2027) с пятью этапами, цветовым кодированием по фазам и вертикальными линиями ключевых вех:

| Веха | Месяц | Цвет |
|---|---|---|
| M3: Облако готово | Июль 2026 | 🟢 Зелёный |
| M6: Домены изолированы | Октябрь 2026 | 🔵 Синий |
| M8: Аналитика работает | Декабрь 2026 | 🟡 Жёлтый |
| M10: Портал запущен | Февраль 2027 | 🟣 Фиолетовый |
| M12: Полный запуск | Апрель 2027 | 🟠 Оранжевый |

## Детализация этапов

---

### Этап 1: Фундамент облачной инфраструктуры (Месяцы 1-3)

**Бизнес-цель**: Создать базовую инфраструктуру для миграции и развития доменов.

| Проект | Описание | Ожидаемый результат | Ответственная команда | Ресурсы |
|---|---|---|---|---|
| Развёртывание Yandex Cloud | Настройка VPC, подсетей, security groups, NAT через Terraform | Готовая облачная среда с IaC | DevOps / Platform team (3 чел.) | Yandex Cloud subscription, Terraform |
| Развёртывание Kafka | Managed Kafka в Yandex Cloud, топики для доменов | Работающая событийная шина | Platform team (2 чел.) | Managed Kafka, 3 брокера |
| IAM/SSO | Развёртывание Keycloak, интеграция с AD, настройка RBAC | Единая аутентификация и авторизация | Security team (2 чел.) | VM для Keycloak, PostgreSQL |
| CI/CD | Настройка GitLab CI, Docker Registry, pipeline templates | Автоматизированные сборка и деплой | DevOps (2 чел.) | GitLab, Container Registry |

---

### Этап 2: Выделение доменов (Месяцы 2-6)

**Бизнес-цель**: Обеспечить независимое развитие подразделений, изолировать данные согласно регуляторным требованиям.

| Проект | Описание | Ожидаемый результат | Ответственная команда | Ресурсы |
|---|---|---|---|---|
| Домен Финтех | Миграция финансовых данных и логики из DWH в отдельные сервисы и PostgreSQL. Интеграция через Kafka. | Финтех-сервисы работают автономно, данные изолированы (требования ЦБ) | FinTech team (5 чел.) + DBA (1 чел.) | Managed PostgreSQL, VMs |
| Домен Клиники | Перенос логики управления пациентами, персоналом, инвентарём из DWH. Новый веб-UI для операторов. | Клиники работают на собственных сервисах. Медданные изолированы (152-ФЗ) | Clinic team (5 чел.) + DBA (1 чел.) | Managed PostgreSQL, VMs |
| Домен ИИ | Переключение ИИ-сервисов с ESB на Kafka. Создание Feature Store. | ИИ-сервисы получают данные через Kafka, не зависят от DWH | AI team (3 чел.) | GPU VMs, S3, ClickHouse |
| Домен Головной офис | Определение KPI и метрик, настройка data governance | Формализованные требования к отчётности и качеству данных | Analytics team (2 чел.) | — |

---

### Этап 3: Платформа данных (Месяцы 3-8)

**Бизнес-цель**: Обеспечить быструю аналитику по всем направлениям, создать основу для портала самообслуживания.

| Проект | Описание | Ожидаемый результат | Ответственная команда | Ресурсы |
|---|---|---|---|---|
| Data Lake | Настройка S3 Object Storage, организация слоёв (raw/cleaned/curated) | Централизованное хранилище сырых данных | Data Platform team (3 чел.) | S3 buckets |
| Analytical Store | Развёртывание ClickHouse, проектирование витрин данных | Аналитические запросы выполняются за секунды | Data Platform team (2 чел.) + Analyst (1 чел.) | Managed ClickHouse cluster |
| ETL/ELT | Настройка Airflow для оркестрации, dbt для трансформаций | Автоматическое обновление витрин данных из доменов | Data Engineers (3 чел.) | VM для Airflow, dbt |
| Миграция из DWH | Поэтапный перенос исторических данных (сотни ТБ) | Исторические данные доступны в новом хранилище | Data Engineers (2 чел.) + DBA (1 чел.) | Сеть, промежуточное хранилище |

---

### Этап 4: Портал самообслуживания (Месяцы 6-10)

**Бизнес-цель**: Реализовать витрину данных — главное требование руководства.

| Проект | Описание | Ожидаемый результат | Ответственная команда | Ресурсы |
|---|---|---|---|---|
| MVP портала | React-приложение с интеграцией Keycloak, каталог данных, базовые отчёты | Сотрудники могут просматривать готовые дашборды в рамках своего уровня доступа | Frontend (3 чел.) + Backend (2 чел.) | VMs, CDN |
| BI Engine | Развёртывание Superset, подключение к ClickHouse, миграция ключевых дашбордов с Power BI | BI доступен через портал, отчёты формируются за секунды | BI team (2 чел.) + Data Analyst (2 чел.) | VM для Superset |
| Конструктор отчётов | Интерфейс для создания пользовательских отчётов с drag-and-drop | Аналитики могут конструировать отчёты без помощи IT | Frontend (2 чел.) + Backend (2 чел.) | — |

---

### Этап 5: Масштабирование и интеграция партнёров (Месяцы 10-12)

**Бизнес-цель**: Подключить новые бизнес-направления, завершить модернизацию интерфейсов.

| Проект | Описание | Ожидаемый результат | Ответственная команда | Ресурсы |
|---|---|---|---|---|
| Фармацевтика | Создание домена для фармацевтического партнёра, интеграция через Kafka | Данные о препаратах и поставках доступны в аналитике | Integration team (2 чел.) + Partner team | Kafka топики, ETL |
| Электроника | Создание домена для производителя мед. оборудования | Данные об оборудовании, гарантиях, обслуживании в аналитике | Integration team (2 чел.) + Partner team | Kafka топики, ETL |
| Замена PowerBuilder | Полный переход операторов клиник на веб-интерфейс | Отказ от PowerBuilder, единый веб-интерфейс | Clinic Frontend (3 чел.) | — |

## Ключевые вехи (Milestones)

| Веха | Срок | Критерий достижения |
|---|---|---|
| Облачная инфраструктура готова | M3 | Terraform apply успешен, сеть, IAM, Kafka работают |
| Домены финтех и клиник выделены | M6 | Сервисы работают автономно, данные изолированы |
| Аналитическое хранилище работает | M8 | Запросы в ClickHouse выполняются < 10 сек |
| MVP портала запущен | M10 | Бизнес-пользователи могут видеть дашборды |
| Конструктор отчётов доступен | M12 | Аналитики создают собственные отчёты |
| Партнёры подключены | M12 | Данные фармацевтики и электроники в аналитике |
