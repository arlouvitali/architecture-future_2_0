# Data Flow Diagram — Потоки данных между доменами «Будущее 2.0»

## Описание

Диаграмма отражает потоки данных между доменами целевой архитектуры. Каждый домен владеет своими данными и взаимодействует с остальными через событийную шину (Kafka) и API Gateway. Платформа данных агрегирует данные из всех доменов для аналитики.

## DFD Level 0 — Контекстная диаграмма

Файл: [dfd_level0.drawio](dfd_level0.drawio)

Диаграмма показывает экосистему «Будущее 2.0» как единую систему и шесть внешних участников, обменивающихся с ней данными:

| Внешний участник | Входящие данные | Исходящие данные |
|---|---|---|
| Оператор клиники | Данные пациентов, назначения | Расписание, карты пациентов |
| Бизнес-аналитик | Запросы на отчёты | Отчёты, дашборды |
| Руководитель | Запросы метрик | KPI, управленческие дашборды |
| Клиент финтех | Заявки на кредит, платежи | Статус кредита, выписки |
| Фармацевтический партнёр | Каталоги препаратов, поставки | Заказы на препараты |
| Производитель электроники | Каталоги оборудования, гарантии | Заказы на оборудование |

## DFD Level 1 — Потоки между доменами

Файл: [dfd_level1.drawio](dfd_level1.drawio)

Диаграмма раскрывает внутреннюю структуру системы: пять доменов, платформу данных и интеграцию с партнёрами. Потоки организованы слева направо без пересечений:

**Домены (левый столбец)** → **Kafka (центр)** → **ETL (обработка)** → **Хранилища** → **Аналитика и отчётность**

### Ключевые потоки на диаграмме

| # | Источник | Приёмник | Данные | Направление |
|---|---|---|---|---|
| 1 | Клиники | Kafka | События: пациенты, записи, инвентарь, персонал | → |
| 2 | Финтех | Kafka | События: заявки, платежи / Данные клиентов для скоринга | ↔ |
| 3 | ИИ-сервисы | Kafka | Мед. данные (обезличенные) / Результаты диагностики | ↔ |
| 4 | Kafka | ETL | Все доменные события | → |
| 5 | Legacy DWH | ETL | Историческая миграция (batch) | → (пунктир) |
| 6 | ETL | Data Lake | Сырые данные | → |
| 7 | ETL | ClickHouse | Агрегаты, витрины | → |
| 8 | ClickHouse | BI Engine | Визуализация | → |
| 9 | ClickHouse | Портал | Ad-hoc запросы | → |
| 10 | ClickHouse | Головной офис | Консолидированные данные, KPI | → |
| 11 | BI Engine | Портал | Встроенные дашборды | → |
| 12 | Kafka | Фармацевтика | Каталоги, заказы | ↔ |
| 13 | Kafka | Электроника | Каталоги, заказы | ↔ |

## Описание ключевых бизнес-сценариев

### 1. Интеграция нового финтех-сервиса

```
Клиент → FinTech API → FinTech DB
                     → Kafka [событие: "заявка на кредит создана"]
                          → AI Services [скоринг на основе ML]
                          → ETL → Analytical Store [метрики кредитования]
                          → Corporate Domain [финансовая отчётность]
```

Финтех-домен публикует событие в Kafka. ИИ-сервисы подписаны на события для скоринга. Платформа данных агрегирует для отчётности. Ни один домен не обращается напрямую к БД другого домена.

### 2. ИИ-диагностика медицинских данных

```
Оператор → Clinic API → Clinic DB [запись результатов обследования]
                      → Kafka [событие: "новое обследование"]
                           → AI Services [анализ, диагностика]
                           → Kafka [событие: "диагноз поставлен"]
                                → Clinic API [рекомендация в карту]
```

Данные передаются через события. ИИ-сервисы получают только обезличенные медицинские данные для анализа. Медицинские карты и истории болезней остаются внутри домена клиник.

### 3. Построение управленческого отчёта

```
Руководитель → Портал самообслуживания → BI Engine
                                       → Analytical Store (ClickHouse)
                                            ← ETL ← Kafka ← [все домены]
```

Аналитик или руководитель заходит на портал, выбирает метрики и срезы. Запрос идёт в ClickHouse, где данные уже агрегированы из всех доменов. Отчёт формируется за секунды.

### 4. Подключение фармацевтического партнёра

```
Фармацевтика → Kafka [каталоги, остатки, поставки]
                  → Clinic Domain [обновление данных об инвентаре]
                  → ETL → Data Lake [аналитика по закупкам]
```

Новый партнёр интегрируется через Kafka — публикует свои события и подписывается на нужные. Не требуется менять DWH или другие домены.
